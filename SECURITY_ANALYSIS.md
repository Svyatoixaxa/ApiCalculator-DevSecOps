# Анализ безопасности API Calculator

## 1. Цель и инструменты

Semgrep анализирует исходный код и конфигурацию по правилам без запуска приложения (SAST). Trivy сопоставляет версии компонентов Docker-образа с базами известных уязвимостей (анализ состава ПО, SCA). Эти методы дополняют друг друга и не гарантируют отсутствие всех возможных уязвимостей.

## 3. Дополнительные проблемы, выявленные при просмотре исходников

- Обычный `float` допускал NaN/Infinity; неконечные результаты могли приводить к ошибкам сериализации JSON.
- Оператор `**` для отрицательного основания и дробной степени может возвращать комплексное число; большие степени могут вызвать OverflowError.
- Проверка импорта API в CI не подтверждала корректность операций; запрос `/version` проверял HTTP-код, но не значение версии.
- Отчёты были только в логах; образ был временным на runner. Trivy собирал отдельный образ, который мог отличаться от ранее проверенного.

## 4. Внесённые изменения

| Проблема | Изменение | Статус |
|---|---|---|
| Теги внешних Actions | Полные commit SHA, read-only permissions, отключение сохранения git credentials | В конфигурации |
| Root в контейнере | USER 10001:10001, отдельный пользователь и группа | Подтверждено в CI: UID 10001 |
| Некорректный ввод | FiniteFloat, math.isfinite, обработка ValueError/OverflowError | 6 групп тестов успешно в GitHub Actions |
| Слабая проверка CI | Автотесты, проверка результата /add и точного значения /version | Подтверждено запуском №17 |
| Разные образы | Trivy сканирует TAR того же образа, который был запущен в CI | Настроено |
| Отсутствие отчётов | JSON-артефакты, TAR образа; логи | Настроено |
| Устаревание компонентов | docker build --pull, Dependabot, фиксированные версии сканеров | Настроено |

Не добавлялись msgpack/setuptools/urllib3 в requirements.txt без проверки наличия и необходимости: добавление неиспользуемых пакетов увеличивает поверхность атаки. После сканирования нового образа, если эти пакеты присутствуют и уязвимы, установить источник (`docker run --rm calculator-api:1.0.0 python -m pip list` и `pip show ИМЯ_ПАКЕТА`), сверить advisory и FixedVersion, обновить родительскую зависимость или совместимое ограничение версии, пересобрать образ и повторить тесты. Если пакет не нужен — исключить его, а не устанавливать специально.

### Semgrep

Semgrep 1.186.0 с набором правил p/default обнаружил 4 замечания, обозначенные инструментом как blocking: три записи Dependabot без периода ожидания (cooldown) и одно замечание о передаче вывода curl в интерпретатор Python. В данном случае Python выполняет фиксированный код разбора JSON, а не код из HTTP-ответа; находку следует оценить как потенциальное ложное срабатывание в данном контексте. Для устранения предупреждения можно сохранять ответ curl в файл, затем разбирать JSON из файла. Для Dependabot рекомендуется добавить `cooldown: {default-days: 7}` в каждый из трех блоков updates. Старые замечания о тегах Actions и отсутствии USER в новом отчете не обнаружены.

### Trivy

Trivy 0.76.2 обнаружил 53 записи HIGH в системных пакетах Debian 13.8 и 5 записей HIGH в Python-пакетах; CRITICAL не обнаружено. Число записей не равно числу уникальных CVE: одна уязвимость может затрагивать несколько пакетов. Примеры системных компонентов: util-linux, OpenSSL, SQLite, ncurses. Для msgpack следует ориентироваться как минимум на 1.2.3 с учетом обеих находок. Для всех трех пакетов сначала необходимо определить источник установки и необходимость пакета, затем обновить или исключить его и повторно провести тестирование. Системные пакеты следует обновлять по мере выхода исправлений Debian и пересобирать базовый образ; до выхода исправлений учитывать применимость уязвимостей и ограничивать доступ.

Сравнение не является строго контролируемым экспериментом: изменились версия Debian, база и правила сканеров, а также отключен фильтр ignore-unfixed. Рост числа записей Trivy сам по себе не доказывает ухудшение защищенности кода. Зеленый статус CI означает выполнение проверок, а не отсутствие уязвимостей: сканирование настроено в отчетном режиме. Исправления новых находок не заявлены как выполненные.

## 6. Дальнейшие меры

Перейти к блокирующему режиму (`semgrep scan --error`, `trivy image --exit-code 1`), закреплять образы по digest, регулярно проверять и обновлять зависимости, добавить HTTPS, ограничение частоты запросов и мониторинг при публикации API во внешнюю сеть. Проверять область применения CVE и не интерпретировать наличие пакета как доказательство эксплуатации. Нагрузочное тестирование — отдельная задача; данный проект проверяет функциональность и базовые меры защиты.
